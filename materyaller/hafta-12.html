Kullanıcı arayüzü, oyun döngüsü ve kayıt

Puan, süre ve ilerleme göstergeleri, öğrenciye ne yaptığını ve ne öğrendiğini bildiren kanaldır. Bu hafta arayüzü kurup oyunun başlangıç, bitiş ve yeniden deneme döngüsünü tamamlıyor, verileri kalıcı hâle getiriyoruz.

12. haftaOkuma süresi yaklaşık 16 dk1 etkileşim
01

Geri bildirim ve öğrenme

Geri bildirim, öğrenmeyi en çok etkileyen etkenler arasında gösterilir (Hattie ve Timperley, 2007). Oyunlar bu açıdan elverişlidir: her eylemin sonucu hemen görülür ve eylem tekrarlanabilir. Ancak arayüz yanlış kurulduğunda bu avantaj kaybolur. Eğitsel oyunlarda sık görülen üç sorun şunlardır:

  • Gecikmiş geri bildirim. Doğru ya da yanlış bilgisi yalnızca oyunun sonunda verilirse öğrenci hangi eyleminin doğru olduğunu ilişkilendiremez.
  • Yalnızca toplam puan. "Puan: 40" bilgisi öğrenciye neyi yanlış yaptığını söylemez. "3 doğru, 1 yanlış; paydası farklı kesirlerde zorlandın" gibi bir özet söyler.
  • Yalnızca kayıp gösteren sayaç. Sürekli azalan bir can göstergesi hataya odaklanır. İlerlemeyi gösteren bir gösterge çoğu durumda daha uygundur.

03

Canvas ve çözünürlükten bağımsız yerleşim

Bu derste arayüz, Unity'nin nesne tabanlı arayüz sistemi olan uGUI ile kurulur: GameObject → UI menüsünden eklenen her öğe bir Canvas'ın içinde yer alır. Metinler için Text - TextMeshPro kullanılır; ilk kullanımda Unity gerekli dosyaları içe aktarmayı önerir.

Arayüzün en sık görülen sorunu, geliştirme ekranında düzgün görünen yerleşimin projeksiyonda ya da başka bir bilgisayarda kaymasıdır. Bunu önlemek için iki ayar yapılır:

  1. Canvas'taki Canvas Scaler bileşeninde UI Scale Mode ayarı Scale With Screen Size yapılır ve bir referans çözünürlük (örneğin 1920 × 1080) verilir. Arayüz bu çözünürlüğe göre orantılı olarak ölçeklenir.
  2. Her öğe bulunması gereken kenara ya da köşeye çapalanır. Sol üst köşeye çapalanan bir puan göstergesi, ekran genişlese de sol üstte kalır.

Öğeleri ekranın tam kenarına yerleştirmemek de önemlidir. Projeksiyonda kenarlar kesilebilir, telefonlarda çentik alanı öğeleri kapatabilir.

SkorYonetici.cs
using UnityEngine;
using TMPro;

// Oturum boyunca doğru ve yanlış sayısını tutar, arayüzü günceller.
public class SkorYonetici : MonoBehaviour
{
    public static SkorYonetici Ornek { get; private set; }

    [SerializeField] private TMP_Text skorMetni;

    private int dogru;
    private int yanlis;

    void Awake()
    {
        // Sahnede tek bir skor yöneticisi olmasını sağla
        if (Ornek != null && Ornek != this) { Destroy(gameObject); return; }
        Ornek = this;
    }

    public void Kaydet(bool dogruMu)
    {
        if (dogruMu) dogru++; else yanlis++;
        skorMetni.text = $"Doğru: {dogru}   Yanlış: {yanlis}";
    }

    public string OturumOzeti()
    {
        int toplam = dogru + yanlis;
        if (toplam == 0) return "Henüz deneme yapılmadı.";
        int oran = Mathf.RoundToInt(100f * dogru / toplam);
        return $"{toplam} denemede {dogru} doğru (%{oran}).";
    }
}

9. haftadaki seçenek script'inde Debug.Log satırlarının yerine SkorYonetici.Ornek.Kaydet(true) ya da Kaydet(false) yazıldığında sonuçlar ekranda görünür. Ornek alanı, sahnedeki tek skor yöneticisine her script'ten erişmeyi sağlar. Bu kalıba singleton denir; büyük projelerde sakıncaları vardır, ancak bu derste geliştirilen prototipler için yeterlidir.

04

Oyun döngüsü ve sahne geçişleri

Bir prototipin oyun olarak tamamlanması için döngüsünün kapanması gerekir: başla, oyna, bitir, yeniden dene. Eğitsel oyunlarda yeniden deneme adımı özellikle önemlidir; öğrencinin yanlışının ardından hemen tekrar deneyebilmesi gerekir.

OyunDongusu.cs
using UnityEngine;
using UnityEngine.SceneManagement;

public class OyunDongusu : MonoBehaviour
{
    [SerializeField] private GameObject bitisPaneli;

    public void OyunuBitir()
    {
        bitisPaneli.SetActive(true);
        Time.timeScale = 0f;            // oyunu dondur
    }

    // Bitiş panelindeki "Yeniden dene" düğmesine bağlanır
    public void YenidenDene()
    {
        Time.timeScale = 1f;            // sahne yüklemeden önce geri al
        SceneManager.LoadScene(SceneManager.GetActiveScene().name);
    }
}

Time.timeScale sıfırlandıktan sonra 1'e döndürülmezse yeni yüklenen sahnede hiçbir şey hareket etmez. Hata iletisi üretilmediği için bu sorunun nedeni geç fark edilir. Başka bir sahneye geçilecekse o sahnenin File → Build Profiles penceresindeki sahne listesine eklenmiş olması gerekir.

05

Verileri saklamak

Sahne değiştiğinde önceki sahnedeki nesneler silinir. Bir verinin sahneler arasında ya da oyun kapatılıp açıldığında korunması için saklanması gerekir. Küçük veriler için PlayerPrefs kullanılır:

// En yüksek doğru sayısını sakla
int enIyi = PlayerPrefs.GetInt("EnIyi", 0);
if (dogru > enIyi)
{
    PlayerPrefs.SetInt("EnIyi", dogru);
    PlayerPrefs.Save();
}

Birden fazla alanı olan veriler için bir sınıf [System.Serializable] ile işaretlenir ve JsonUtility.ToJson ile metne çevrilerek saklanır; JsonUtility.FromJson ile geri okunur.

PlayerPrefs kolayca okunup değiştirilebilir ve büyük veri için tasarlanmamıştır. Ders projeleri için yeterlidir. Gerçek bir sınıfta öğrenci verisi toplayan bir uygulama geliştirilecekse kişisel verilerin korunmasına ilişkin yükümlülükler ayrıca düşünülmelidir.

3B'de dünya içi arayüz, eğitsel açıdan ilginç bir olanaktır: bir ölçüm değerini ekranın köşesinde değil, sahnedeki bir ölçüm aletinin ekranında göstermek, verinin ortamın parçası olarak algılanmasını sağlar. Teknik olarak daha zahmetli olduğu için prototipte önce ekran arayüzüyle başlanması önerilir.

07

Ders içi uygulama

  1. Projenize SkorYonetici'yi ekleyin ve 9. haftadaki seçenekleri ona bağlayın.
  2. Bir bitiş paneli oluşturun: oturum özeti ve "Yeniden dene" düğmesi.
  3. Oyun penceresinin çözünürlüğünü değiştirerek arayüzün doğru ölçeklendiğini kontrol edin.

Tekrar soruları

  1. Arayüz geliştirme ekranında düzgün, projeksiyonda kaymış görünüyor. Hangi iki ayar kontrol edilir?
    Yanıtı göster

    Canvas Scaler'ın Scale With Screen Size olması ve öğelerin doğru kenara çapalanmış olması.

  2. Yeni sahne açıldı ama hiçbir şey hareket etmiyor, hata da yok. Olası neden nedir?
    Yanıtı göster

    Time.timeScale önceki sahnede 0 yapılmış ve geri alınmamış.

  3. Eğitsel bir oyunda "Puan: 40" yerine nasıl bir geri bildirim tercih edilir?
    Yanıtı göster

    Hemen verilen ve neyin doğru ya da yanlış yapıldığını gösteren bir geri bildirim; oturum sonunda da konu bazında bir özet.
